# Protocol and benchmark contract v1

This is the shared reference for both implementations. The [design proposal](../tcp-dotnet11-cpp23-benchmark-plan.md) explains the experimental rationale. Both executables provide `server`, `client`, `process`, and `selftest` commands. Options use `--name value`; unknown or duplicate options and invalid ranges fail with a nonzero exit code.

## Wire

All integers are big endian. Header: payload length u32, version u16 (=1), type u16, sequence u64. Requests start at sequence 1 and increment exactly by one including controls; responses echo sequence and type|0x8000. Hard body limit 16777216 bytes. Data must be inside an epoch; Begin cannot nest; End ends it; a new Begin is allowed. EOF between frames is clean, inside one is truncation. No automatic retries. Response bodies may exceed configured tiny input frame sizes; type-specific bounds apply.

* Begin(1): exactly 32 manifest hash bytes. Server CLI `--manifest-hash` is 64 hex digits, default 64 zeros for manual tests. Mismatch closes connection. Response empty. Reset epoch counters, keep retention.
* JsonBatch(2): nonempty JSON byte payload. Response: records u64, digest u64 (16 bytes).
* End(3): zero bytes. Response exactly 1056 bytes: batches u64, payload_bytes u64, records u64, batch_digest u64, then 64 bucket counts u64, then 64 bucket sums i64. No interleaving. All counts are for this epoch only.

Version/type/sequence/length errors close without success ACK. Accept whitespace-only? No: body must parse as an array. Empty array is valid and returns zero records and FNV offset. Limit one epoch to 1e9 records; checked counters. End summary batch_digest is FNV over each successful request's sequence(u64), record_count(u64), result_digest(u64), in that order. Initialize it to FNV offset. In `transport` mode receive full bodies without JSON decoding, return records=0 and digest=payload_length; category arrays remain zero, but bytes/batches and batch_digest still update.

## Strict JSON and canonical digest

Root array of objects; exactly these seven required fields, any property order, no unknown/duplicate names (compare unescaped names): id u64, timestamp_ns u64, source u32, kind string, value_milli i64 in [-1000000,1000000], flags u32, message string. `kind` is exactly `kind00` ... `kind15` (ordinal). Number tokens must be JSON integers, not floating/exponent/quoted; negative zero is allowed for signed value_milli only. Reject minus signs for unsigned fields, including -0. Strings are strict Unicode, reject invalid UTF-8 and lone surrogate escapes; decoded message UTF-8 length <=4096. No BOM/comments/trailing commas/multiple roots. Only JSON whitespace after root. Depth maximum 4, with root array depth 1; the schema itself permits no nested values. Escaped valid property names accepted.

FNV-1a 64 offset=14695981039346656037, prime=1099511628211, unsigned wrap modulo 2^64. Per batch start at offset. For every record in array order hash exactly: byte 0x52; id u64; timestamp_ns u64; source u32; kind index u8; value_milli two's-complement i64; flags u32; decoded message byte length u32; decoded UTF-8 message bytes. All integers big endian. Bucket=kind*4+(flags&3). Update bucket count and signed value sum. Property order/escaping never changes the result. Canonical retention size=38+decoded_message_length bytes per row.

Modes: aggregate, retain-reuse, retain-allocate, transport. Commit only after entire valid batch. Retain modes materialize owned rows/message data, then calculate result from those rows; retain up to `--retain-batches` (default8) AND `--retain-bytes` (default67108864) per connection, evict oldest before commit as needed. A batch bigger than retention capacity fails atomically. Revisit and verify retained batch digest before eviction and on graceful connection end. Reuse mode recycles evicted storage, allocate mode releases it. Scratch needed to validate a new batch is distinct from committed retained state. Aggregate should avoid per-record/per-frame managed allocations after capacity warmup where practical. Report actual allocations, never promise zero.

## Corpus format (.bin)

Header: ASCII `TCPBCH01` (8 bytes), frame_count u32, reserved u32=0. Then for each frame: payload_length u32; expected_records u64; expected_digest u64; 64 expected bucket_counts u64; 64 expected bucket_sums i64; raw UTF-8 payload bytes. Thus metadata per frame=1044 bytes. No extra/truncated bytes. Validate lengths/counts before allocating, reject invalid/reserved header. Load outside measurement. Oracle/generator lives in tools/corpus.py, written by parent agent. Binary file hash/JSON sidecar identifies corpus. Client checks data ACK and End full summary against metadata. Corpus is trusted benchmark input only after structural checks.

## Shared CLI

* `server --port 9000 --mode aggregate --max-frame 1048576 --max-connections 32 --workers 4 --manifest-hash <hex> --idle-timeout-ms 5000 --frame-timeout-ms 30000 --retain-batches 8 --retain-bytes 67108864 --socket-buffer 262144 [--output server.json]`. Bind 127.0.0.1. Emit one flushed JSON stdout line `{"event":"ready","port":9000,...}` once listening. Close excess connections. Deadline starts on first header byte, idle timeout only applies while a frame or response is pending (not quiet connection between frames). Bound pending ACK writes too. `--run-seconds 0` default indefinite; positive permits clean automated shutdown with all pending I/O drained safely. `--pause-every 0 --pause-ms 0` are explicitly diagnostic fault switches; implementation may gate individual connection processing and must label results. Cancellation must safely close/drain sockets. Server output contains counters, CPU, memory, runtime/build, receive/send operations and rejection reasons.
* `client --port 9000 --corpus data/smoke.bin --mode aggregate --connections 4 --duration 10 --warmup 2 --window 8 --inflight-bytes 67108864 --rate 0 --arrival steady --seed 42 --manifest-hash <hex> --socket-buffer 262144 --drain-seconds 30 --output result.json`. rate=0 closed loop; >0 total global frames/second scheduled independent of replies. arrival=steady|poisson|burst. Each connection one send owner and concurrent ACK reader; bound outstanding frames AND bytes globally. Never drop silently; record offered/admitted/rejected/timedout. Scheduled arrival remains its original time. Phase durations seconds finite >0 (warmup may 0). Warmup drain then new epoch; measured requests reconciled including drain, window vs cohort denominators distinct. Full ACK/End verification. Failed integrity/nonreconciled runs exit nonzero; deliberate offered-load admission failures remain reported and mark sustainability false. No per-frame stdout. Choose corpus frames by deterministic connection-local cursor (start=connection index, advance=connections modulo frame_count), shared across languages; record this. Use the shared SplitMix64 schedule and exponential transform for Poisson. Burst repeats five seconds at 0.6 times the reference rate and one second at 1.5 times the reference rate.
* `process --corpus ... --mode aggregate --duration 5 --warmup 1 --output ...` full-corpus processing, same functions/checks, excludes TCP; marks control result explicitly.
* `selftest` must test canonical digest, strict JSON including Unicode/number corners, invalid frame no state commit, and retained lifetime/reuse.

Additional implementation-specific diagnostic options must be documented and not silently alter common defaults. Histogram use: preallocated log-linear histogram (exact nanosecond buckets through 1023ns; thereafter 256 linear sub-buckets per power of two) is acceptable if identical in both clients and matching test vectors; report bucket upper bounds and count, do not average quantiles. Explicitly publish this as a justified small dependency-free alternative to planned HDR library. For value>=1024: e=floor(log2(value)); shift=e-8; index=1024+(e-10)*256+((value>>shift)-256); upper bound=((value>>shift)+1)<<shift minus1. Include >=60s overflow counter and maximum separately. Use QPC/Stopwatch and raw integer ticks. Detailed stage timing may sample every1024 frames; basic result includes latency p50/p90/p99/p999/max, CPU, memory and errors. Never silently skip failed samples.

Refinements agreed by both implementation agents: `window` is the GLOBAL frame cap; inflight-bytes is also global. Both allocating retained implementations use fresh owned rows/text buffers with UTF-8 text, so layout semantics match reuse (no managed UTF-16 object-graph variant in this version). Scheduled rejection advances the connection-local corpus cursor; closed loop advances only on admission. SplitMix64 schedule resets each phase, corpus cursors persist through warmup. Values >=60s count as histogram overflow and total samples but have no finite bucket; a quantile with rank in overflow returns null, never a clipped good latency. Server `--control-stdin 1` (default0) enables graceful runner shutdown on `stop` or EOF; emit final server metrics only after I/O lifetime cleanup. Diagnostic thread/handle costs are disclosed.

## Review refinements

Admitted client data has an absolute deadline at measurement-window end plus `--drain-seconds`; an earlier socket operation must not shorten it. Begin/End controls have their own bounded exchanges. `cohort_seconds` is T0 through the later of window end or data-worker completion, including failure waiting but excluding final End controls. `drain_seconds` is the observed interval after window end until data-worker completion; `drain_limit_seconds` preserves the configured allowance. `timedout` is a subset of `unresolved`, not another term in the accounting equation. Reconcile `admitted = acknowledged + failed + unresolved`, and `offered = admitted + rejected`.

Scheduled demand is the complete finite intended schedule even after an early fatal error. Count undispatched future arrivals as `aborted_schedule_rejected` and as deadline misses; do not invent future closed-loop demand. A fatal client error makes generator adequacy false. Ordinary admission rejection under correctly generated overload remains valid workload evidence, with sustainability false.

Both servers sample every 1024th data frame starting at frame 1024, resetting at Begin. Sampled processing elapsed includes the diagnostic processing pause; retained visit includes eviction verification. Stage p99 requires at least 10,000 samples and stage p99.9 requires at least 1,000,000; otherwise those fields are null, while raw bucket counts and maxima remain available. Client empirical tails remain raw observations with sample counts, not automatically justified headline claims. Per-size client histograms use five payload classes: <=4 KiB, <=64 KiB, <=256 KiB, <=1 MiB, and larger.

Processing-only controls check full category counts/sums as well as records and digest during both warmup and measurement. Reports retain all input trial rows and expose validity, generator adequacy, failure/timeout/unresolved demand and deadline misses. Invalid, unverified or generator-inadequate runs do not enter comparisons; a pair requires both eligible members. Correctly reconciled overload runs remain labeled evidence. Different corpus identities, durations, warmups, admission windows, seeds or arrival shapes cannot be silently pooled.

## Processing deadlines and storage measurements

The frame budget applies through processing, retained-data verification and response writing. Processing checks the earlier of the absolute frame deadline and the no-progress deadline before work, at every 1024th record during parsing or retained visits, and before commit. Diagnostic waits observe the same budget and server shutdown. An otherwise quiet connection at EOF has no active frame deadline; retained verification still observes shutdown. These are cooperative checks, not hard real-time preemption of library calls, allocation, operating-system scheduling or GC.

All planned eviction candidates are verified before mutating committed retention state. Expired work must not enter the epoch or completed-frame count. Owned-storage capacity measures reachable row/text array or vector capacity, including incoming validation scratch alongside retained batches at its high-water mark. It excludes parser internals, allocator metadata and garbage awaiting collection; process memory and allocation counters remain separate measurements.
